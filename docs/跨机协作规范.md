# Oneleaf 跨机协作规范（Mac ↔ Windows ↔ GitHub）

> 目的：在 Mac 和 Windows 之间来回开发，保证 pull 下来就能跑，不出现莫名其妙的兼容问题。
> 适用仓库：`https://github.com/upperone-F/oneleaf.git`

---

## 一、结论先行

**Flutter / Dart 源码是跨平台的**——同一份代码在 Mac 和 Windows 都能编译、能运行。你担心的"Mac 写了一部分 push 上去，Windows pull 下来不兼容"，只要按本规范做，**不会发生**。

真正需要处理的只有 4 类问题，其中 3 类已经用配置文件一次性解决：

| 问题 | 状态 | 解决方式 |
|------|------|----------|
| 换行符 CRLF / LF 不一致 | ✅ 已解决 | `.gitattributes` 统一 LF |
| 系统垃圾文件（`.DS_Store` / `Thumbs.db`）混入 | ✅ 已解决 | `.gitignore` 已忽略 |
| 本机私密配置 / 签名 / SDK 路径被提交 | ✅ 已解决 | `.gitignore` + 环境变量 |
| **iOS 只能在 Mac 编译**（硬限制） | ⚠️ 需流程配合 | 见第四节 |

## 二、已落地的配置（不用再管）

### 2.1 `.gitattributes` —— 换行符统一

```
* text=auto eol=lf
*.dart / *.yaml / *.json / *.md / *.sh / gradlew  →  LF
*.png / *.jpg / *.webp / *.ttf / *.jks / *.keystore → binary（不转换）
```

作用：无论在哪台机器 checkout，文本文件都变成 LF，二进制文件原样保留。
**这解决了 90% 的"跨平台改一行结果整个文件都变红"问题。**

### 2.2 `.gitignore` —— 只同步源码，不同步机器产物

已忽略：`.DS_Store`、`Thumbs.db`、`Desktop.ini`、Flutter 构建产物、`local.properties`（含本机 Android SDK 路径）、签名密钥（`*.jks`、`key.properties`）、`.env`、IDE 配置等。

**特别说明**：Flutter 默认的 `android/app/debug.keystore` 故意**不忽略**——它要提交，保证两台机器 debug 签名一致，否则会出现"装了新包就要先卸载旧包"的怪现象。正式的 release 签名才不入库。

## 三、日常开发工作流（切换机器时照做）

```bash
# 1. 开始工作前，先同步
git pull --rebase

# 2. 写代码 → 检查 → 提交
flutter analyze
dart format .
git add .
git commit -m "feat: xxx"

# 3. 推送
git push

# 4. 换到另一台机器
git pull --rebase
flutter pub get          # 依赖若变，重新拉取（pubspec.lock 保证版本一致）
```

**三条习惯**：
1. **先 pull 再写**，避免分叉；
2. **同一时间只在一台机器上改同一个文件**，改完就 push；
3. **切换机器前确保工作区干净**（`git status` 无未提交内容）。

## 四、iOS 的硬限制（唯一真正"不兼容"的地方）

**事实**：iOS App 必须用 macOS + Xcode 编译。Windows 上**无法**执行 `flutter build ios`。这不是配置问题，是 Apple 的限制。

**应对方案（三选一，按推荐排序）**：

| 方案 | 做法 | 适合 |
|------|------|------|
| **① CI 云端编译（推荐）** | GitHub Actions 用 macOS runner 自动编译 iOS，Windows 上 push 代码也能验证/出包 | 双端都开发，想省事 |
| ② 分工 | Mac 只负责 iOS 相关（编译、打包、上架），Windows 负责 Dart 共享代码 + Android | 有明确分工 |
| ③ 云端 Mac 租用 | 用 MacinCloud 等按小时租 macOS 机器 | 偶尔需要 iOS 出包 |

> 即使 iOS 只能在 Mac 编译，**Dart 业务代码、UI、Android 在 Windows 上完全正常开发**。iOS 的原生目录（`ios/`）文件本身也是文本，可以任意机器编辑、提交，只是"编译"这步要在 Mac 或 CI 上做。

## 五、公钥/私钥与本机配置管理

绝不入库的东西，两台机器各自配一份：

| 内容 | Mac | Windows | 管理方式 |
|------|-----|---------|----------|
| Android release 签名 | `key.properties` + `.jks` | 同 | 放各自用户目录，CI 用 Secrets |
| iOS 签名证书 / 描述文件 | Xcode 钥匙串 | 不适用 | 不进仓库 |
| API Key / 后端地址 | `.env` | `.env` | 提交 `.env.example` 作模板，真值各机自己填 |
| Android SDK 路径 | `local.properties` | 同 | Flutter 自动生成本地文件，已忽略 |

## 六、 Flutter 版本一致性（避免"你这能跑我这就报错"）

两台机器 Flutter / Dart 版本不一致，是跨机问题的高发区。推荐用 **FVM** 锁定版本：

```bash
# 首次在仓库里（只需做一次）
dart pub global activate fvm
fvm use 3.24.5          # 换成项目锁定版本
# 会生成 fvm_config.json（已配置提交进仓库）

# 另一台机器 pull 后
fvm install             # 按 fvm_config.json 自动装同版本
fvm flutter pub get
fvm flutter run
```

至少要做到：**两机 `flutter --version` 输出一致**。`pubspec.lock` 已提交，依赖版本会跟着锁住。

## 七、提交前自检清单

- [ ] `git status` 里没有 `.DS_Store` / `Thumbs.db`
- [ ] 没有 `local.properties` / `.env` / `key.properties` / `*.jks`
- [ ] `flutter analyze` 无错误
- [ ] `dart format .` 已执行
- [ ] 若改了依赖，`pubspec.lock` 一并提交
- [ ] commit message 写清楚改了什么

## 八、常见"灵异现象"速查

| 现象 | 原因 | 解决 |
|------|------|------|
| 只改了一行，整个文件都显示被修改 | 换行符不一致 | 确认 `.gitattributes` 生效；必要时 `git add --renormalize .` |
| Windows 上 `gradlew` 报 `\r` 错误 | shell 脚本被转成 CRLF | `.gitattributes` 已强制 LF；重新 checkout |
| 装了新 debug 包提示要先卸载 | 两机 debug 签名不同 | 确认 `debug.keystore` 已提交且两机一致 |
| "在我这能跑，在他那报错" | Flutter 版本 / 依赖版本不同 | 用 FVM + 提交 `pubspec.lock` |
| iOS 在 Windows 上编译失败 | Apple 硬限制 | 走 CI / Mac 编译，见第四节 |
| 文件名大小写问题（Mac 不敏感，CI/Linux 敏感） | import 路径大小写不一致 | 统一小写 + 下划线命名，import 严格匹配 |
