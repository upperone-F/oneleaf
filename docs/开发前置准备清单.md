## 2. 软件环境

### 通用（Mac / Windows 都要）

- [ ] **Git**（✅ 本机已有 2.50.1）— 按《跨机协作规范.md》配好换行符规则
- [ ] **Node.js 20 LTS**（✅ 本机已有 22.22.2）— 后端 NestJS 用
- [ ] **Docker Desktop** — ❌ 本机未装；**最省事的数据库方案**（一键起 PostgreSQL + pgvector）
- [ ] **VS Code** — 装 Dart / Flutter 插件即可（**不需要 Android Studio 当编辑器**；它最多只作 SDK 安装器，见下方方案 B）

### Android 开发链（本机当前重点，两机都要装）

> **关键结论**：不用装完整 Android Studio，但 **JDK + Android SDK 这两个内核必须装**——VSCode 只替代"IDE 编辑器"这一层，替代不了 Google 的 Android 构建工具链。下面给两条路线，**推荐方案 A**。

**方案 A：纯轻量（推荐，日常只用 VSCode）**

- [ ] **JDK 17** — ❌ 本机未装（之前检测是假阳性，`java_home` 报找不到运行时）。装法：`brew install openjdk@17`（Mac）
- [ ] **Android SDK 命令行工具**（commandline-tools / `sdkmanager`）— 不装 IDE，直接命令行装 SDK
- [ ] 用 sdkmanager 装 **platform-tools（adb）+ platforms;android-34 + build-tools;34.0.0**（版本随 Flutter 要求调整）
- [ ] 手动接受 SDK licenses：`yes | sdkmanager --licenses`
- [ ] 设环境变量 `ANDROID_HOME`（macOS 写进 `~/.zshrc`，Windows 写进系统变量），两机都要设
- [ ] 一台 **Android 真机**（开发者选项 + USB 调试）— 本方案无图形模拟器，靠真机跑
- [ ] 验证：`adb devices` 能看到设备、`fvm flutter doctor` 的 Android 项全绿

**方案 B：装一次 Android Studio 当"安装器"（备选）**

- [ ] 装 Android Studio（多约 1GB 体积 + 常驻内存），**只为用它的 SDK Manager 图形装 SDK / 建模拟器**，日常写代码仍用 VSCode
- [ ] 适合：没有真机需要 AVD 模拟器、或不想折腾命令行 license / 环境变量
- [ ] JDK 17 由 Studio 自带，无需单独装

> 两方案**共享的硬依赖**：JDK 17 + Android SDK（platform + build-tools + platform-tools）。差别只在"用图形界面装还是命令行装"以及"要不要 IDE 外壳和模拟器"。SDK 本身省不掉。

**测试机**：再加一台**中低端机**用于轻量体检（包体/启动/内存），这一步两方案都要。

### Flutter（客户端核心）

- [ ] 装 **FVM** 管版本：`dart pub global activate fvm`
- [ ] FVM 锁一个 **Flutter 3.x 稳定版**，两机版本必须一致
- [ ] 验证：`fvm flutter doctor` — **只需 Android 相关项无 ❌**（iOS/Xcode 项此阶段可忽略）

### Windows 特别注意

- [ ] Git for Windows 安装时选 **Checkout as-is, commit LF**，配合已提交的 `.gitattributes`
- [ ] JDK 17 + Android SDK 命令行工具 + Docker Desktop 同样要装（方案 A；无需 Android Studio）
- [ ] ✅ **好消息**：只做 Android 后，Windows 与 Mac 的开发环境能力**完全对等**，之前唯一的硬限制（iOS 只能 Mac 编译）暂时不存在了

## 附：技术栈影响说明（为什么仍保留 Flutter）

只做单端时，"Flutter 一套代码双端"的收益确实变小——单看 Android，原生 Kotlin 的包体更小、启动更快。但：

- **"先做 Android"通常是阶段策略而非永久决定**。一旦后续要 iOS，Flutter 几乎零额外成本；换成 Kotlin 则 iOS 要从头再做一遍。
- Flutter 的翻页动画、定制视觉、端侧语音在 Android 上同样成立，`§5` 的轻量纪律（按需下载语音模型、依赖裁剪、体积门禁）也照样生效，包体目标不变。
- 决策权在你：**若确定长期只做 Android 且把绝对包体/启动速度压到首位**，可改选 Kotlin 原生，这是更轻的选择——但会失去未来低成本扩展到 iOS 的可能。当前默认按 Flutter 推进，只配置 Android 构建。
